# Internationalization

The home, about, projects, contact and donation pages use i18next with Brazilian Portuguese (`pt-BR`), British English (`en-GB`) and Spanish (`es`). The `trakt-tools/` page remains in English without translation. Historical versions in `v1/` and `v2/` retain their original implementations.

The language is selected in this order: the `?lng=pt-BR`, `?lng=en-GB` or `?lng=es` URL parameter, the preference saved in `localStorage`, browser languages, and Portuguese as the default. Regional codes are normalized, for example `en-US` to `en-GB` and `es-ES` to `es`. Switching languages does not reload the page; it saves the preference and updates the URL while preserving other parameters and the hash.

## Adding text

Add the same key to `locales/pt-BR/translation.json`, `locales/en-GB/translation.json` and `locales/es/translation.json`. Keys are flat, semantic English names describing the content's purpose, such as `home.headline`, `about.intro` and `projects.metaDescription`. Use page or component prefixes (`nav`, `footer`, `theme`) and keep the key when the wording changes. Do not derive keys from translated sentences.

The original HTML uses Portuguese text so it remains readable before translations load:

```html
<span data-i18n="nav.about">Sobre</span>
<button data-i18n-aria-label="nav.openMenu" aria-label="Abrir menu">...</button>
<span data-i18n="projects.all" data-i18n-options='{"count":11}'
	>Todos (11)</span
>
```

The attributes `data-i18n-alt`, `data-i18n-title`, `data-i18n-placeholder` and `data-i18n-content` are also supported, including for metadata.

For text with inline markup, use `data-i18n-html`. Translations must retain the same inline elements in the same order across all languages. Text before, between and after those elements may vary: it is updated, added or removed without replacing the elements, their attributes or event listeners. Mark dynamic values with `data-i18n-preserve`, such as the map distance. Do not include user-provided HTML in translation dictionaries.

Elements added by JavaScript are translated automatically when they have these attributes. Wait for `window.siteI18n.ready` before calling `i18next.t()`. When needed, use `window.siteI18n.translateRoot(element)` or listen for the `site:languagechanged` event on `document`. Its `detail.language` contains the active language.

## CDN and tests

Pages load i18next from `https://unpkg.com/i18next@26.4.2/dist/umd/i18next.min.js`. The script uses `defer` and appears before `translation.js` to preserve loading order. The development dependency uses the same version for local tests. When upgrading, update both the page URLs and the development dependency.

Run `bun test` to require identical key sets and non-empty string values in the Portuguese, English and Spanish dictionaries, including keys used by pages and project descriptions. Tests check page and metadata translations in all three languages, language detection, persistence, dynamic content, fallback, DOM preservation and the footer language radios. These checks validate coverage and behavior, not linguistic accuracy.
